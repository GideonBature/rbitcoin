Changed

- **Library tests compile against the normal rlib.** Each library package except `rbitcoin-bench` has one `tests/suite` target (`[lib] test = false` and `doctest = false`, including `rbitcoin-ibd`), so `cargo test` no longer rebuilds the crate under `--cfg test`. Bench still runs with `cargo test -p rbitcoin-bench --lib`. `test-hooks` is gone. Hooks a test arms stay `cfg(debug_assertions)`. A debug node still uses the 8 s outbound connect timeout and still aborts when an io_uring drain leaves SQEs. Initial block download is `rbitcoin-ibd`, and RPC, Electrum, Esplora, and SV2 do not depend on it. The consensus suite is the package's default `corpus` feature (the Core script assembler). Product crates depend on consensus with `default-features = false`, so a node build leaves that assembler out. `rbitcoin-test`'s default scenarios are one `suite` binary; `overlay` stays feature-gated. `NODE_COMPACT_FILTERS` is advertised per peer hub, so one process can run more than one node.
- **Production line-coverage floor is 91%.** Suite tests link the normal rlib, so `#[cfg(test)]` lines are no longer in the LCOV denominator. The measured ratio on this layout is 91.26% (93410/102361). The gate is still unrounded `LH*100 >= LF*91`.
